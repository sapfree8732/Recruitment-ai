## 【资深系统工程师】
- 年薪：open,看候选人情况
- 地点：广州 / 上海(可选)
-JD：
真正的工程挑战，不在于 AI 能否工作——这个问题已有专人负责。
挑战在于：AI 如何稳定、可审计、可扩展、可回滚地工作，并承载企业核心业务。
一个跑得起来的 AI 原型与一个生产级系统之间，隔着的是系统工程。
你的职责，就是跨越这道鸿沟。
你需要负责把一个已被真实使用验证的多租户 AI产品从单机架构扩展到生产规模（数百组织、数千用户），全面负责系统的可靠性、性能、成本控制和发布工程。
我们在寻找什么样的人
系统思维与工程功底是核心能力。AI 相关知识可以入职后学习。
我们曾拒掉入门 AI 很早、但系统能力一般的候选人;也不会拒绝从未接触过 LLM、却在生产系统中积累了多年实战的候选人。
- 硬性要求：
•本科毕业于顶尖 985 院校或海外同水平院校
•运维过多租户的线上生产服务，本人承担过 on-call / 线上事故处理 ；
•容量规划的第一责任人，而不是只参与过架构设计；
•PostgreSQL 深度实战（性能调优、连接池、大规模数据迁移），并有分布式基础组件的生产落地经验（消息队列 / 缓存 / 对象存储 /任务调度，任一即可）；
•资深个人贡献者，至今每天写代码（Python 优先），不是纯管理、纯架构或纯运维背景。资历深厚但已不再写代码的，不在考虑范围
•能熟练使用 AI 编程工具进行日常开发（团队全员 AI 协作开发）
•仍处于一线编码状态。
- 加分项：
•真正的分布式系统经验：共识、复制、分区容忍——而不只是"拆分了几个微服务"
•数据库内核、存储引擎、消息队列、可观测性基础设施背景
•高并发、低延迟系统实战
•除 Python / TypeScript 之外熟悉 Go / Rust / C++，必要时能下沉到更底层
•开源贡献，尤其是基础设施方向
•可靠性工程 / 混沌工程 / SLO 的生产级实战经验
•AI / ML / LLM / 向量数据库相关经验
•英语工作能力
- 不适合这个岗位的人
•挂着"架构师""资深"头衔但一年以上未写代码的
•框架依赖严重，脱离 Spring / Django 便无法编码的
•未曾调试过真正困难的问题——竞态条件、内存泄漏、分布式一致性
•将"能跑通"等同于"可上线"的
•必须等待完整规格说明书才能动手的
•不愿意阅读源码的
